# Final HTML Practice Project

## Production-Quality Website

> Build a professional multi-page website demonstrating your understanding of the complete HTML learning path.

**Challenge Type:** Applied Practice Project

[← Previous Level](<06 - Level 6 - Professional HTML.md>) · [HTML Roadmap](README.md)

---

## Project Brief

Build a professional multi-page website using HTML as the primary focus.

The project should demonstrate that you understand not only HTML syntax, but also:

- Structure
- Semantics
- Forms
- Accessibility
- Metadata
- SEO-conscious markup
- Responsive media
- Maintainability

You may use CSS to make the website presentable, but the assessment focus is the quality of the HTML.

---

## Minimum Requirements

Your project must demonstrate:

- [ ] Semantic HTML
- [ ] Professional document structure
- [ ] Multiple interconnected pages
- [ ] Navigation
- [ ] Accessible forms
- [ ] Native form validation
- [ ] Responsive images
- [ ] Appropriate metadata
- [ ] SEO-conscious HTML
- [ ] Correct heading hierarchy
- [ ] Meaningful alternative text
- [ ] Accessibility considerations
- [ ] Professional repository structure
- [ ] Clear project documentation

---

## Suggested Website

Create a fictional technology/community website with at least:

```text
Home
About
Projects
Events
Contact / Registration
```

Each page should have a clear purpose.

## HTML Quality Review

Before considering the project complete, review:

### Document Structure

- [ ] Correct `<!doctype html>`
- [ ] Appropriate language attribute
- [ ] Correct `<head>`
- [ ] Useful page title
- [ ] Appropriate metadata
- [ ] Semantic `<body>` structure

### Semantics

- [ ] Appropriate landmarks
- [ ] Logical heading hierarchy
- [ ] Sections used intentionally
- [ ] `<div>` not used where a better semantic element exists

### Forms

- [ ] Correct labels
- [ ] Suitable input types
- [ ] Useful `name` attributes
- [ ] Native validation
- [ ] Keyboard usability

### Accessibility

- [ ] Meaningful alternative text
- [ ] Descriptive links
- [ ] Logical headings
- [ ] Native controls
- [ ] Accessible tables where used

### SEO-Conscious HTML

- [ ] Descriptive page titles
- [ ] Useful meta descriptions
- [ ] Crawlable navigation
- [ ] Meaningful internal links
- [ ] Appropriate page structure

### Professional HTML

- [ ] Responsive images where appropriate
- [ ] Maintainable markup
- [ ] No unnecessary nesting
- [ ] No obvious invalid HTML
- [ ] Documentation included

## README Requirements

Your repository `README.md` should explain:

1. Project purpose
2. Pages included
3. HTML concepts demonstrated
4. Accessibility decisions
5. SEO-related decisions
6. Challenges encountered
7. Improvements you would make next

---

## Final Review Question

Before moving to CSS/JavaScript or another front-end stage, you should be able to answer:

> **Could another developer understand the purpose and structure of this website by reading the HTML, even before examining its CSS or JavaScript?**

If the answer is no, review the structure and semantics again.
